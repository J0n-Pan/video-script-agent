## 2 技术栈（PRD 10.3 已确认）

| 层次 | 技术 |
| --- | --- |
| 网页与后端 API | Next.js 14（App Router）+ TypeScript |
| 解析进程 | Node.js + TypeScript 独立进程（`tsx src/worker/index.ts`） |
| 数据访问 | Prisma |
| 本地数据库 | SQLite（`data/app.db`，WAL 模式） |
| 媒体处理 | FFmpeg（随项目安装 `ffmpeg-static` / `ffprobe-static`，**不要求主机预装**） |
| 妙思抓取 | Playwright（随项目安装 `playwright` + chromium 运行时，见第 5 节；缺失时降级为保留链接 + 本地补传） |
| 音频识别 | WebSocket 全双工（Node 内置 `WebSocket`，**不新增依赖**） |
| .env 加载 | 自实现 `src/lib/load-env.ts`（独立进程不自动读取 `.env`，见第 4.5 节） |

网页与解析进程共享 `src/lib` 下的字段类型与统一解析结果结构。

## 3 快速开始

```bash
cd video-script-agent
npm install
cp .env.example .env          # Windows: copy .env.example .env
npm run setup                 # prisma generate + db push + seed 账号
npm run make:test-media       # 可选：生成自备测试素材到 data/samples
npm run dev                   # 同时启动网页（3939）与解析进程
```

访问 http://127.0.0.1:3939。初始账号在部署时配置，仓库内**不提供任何口令**：

| 账号 | 角色 |
| --- | --- |
| `maintainer` | 部署维护人员 |
| `editor` / `editor2` | 编导（`editor2` 仅用于验证多账号隔离） |

首次部署前先在 `.env` 中设置 `SEED_MAINTAINER_PASSWORD`、`SEED_EDITOR_PASSWORD`、
`SEED_EDITOR2_PASSWORD`，再运行 `npm run db:seed`。未设置时种子脚本会使用占位口令并打印提醒，
**该占位口令仅供本地跑通，部署前必须替换**。

分开启动：

```bash
npm run dev:web      # 仅网页
npm run worker       # 仅解析进程
```

### 3.1 日常启动（不需要命令行）

项目根目录下两个脚本，**双击即可**（Windows）：

| 脚本 | 作用 |
| --- | --- |
| `start-workbench.bat` | 启动网页（3939）+ 解析进程，等端口就绪后自动打开浏览器 |
| `stop-workbench.bat` | 关闭上述窗口、按 `data/worker.lock` 结束解析进程、释放 3939 端口 |

- 启动后系统会弹出一个标题为 **`video-script-agent`** 的命令行窗口，网页与解析进程都在里面；
  **关掉这个窗口（或按 Ctrl+C）即全部停止**，也可以直接跑 `stop-workbench.bat`。
- 若网页窗口刚起来就报错（构建缓存 `.next` 损坏），跑一次 `start-workbench.bat clean` 再启动，
  它会先删掉构建缓存重建。
- 只查看 / 编辑 / 导出已有任务时，其实只需要网页：把窗口里错误关掉重开 `npm run dev:web` 也行，
  但没有解析进程就**不能提交新视频**（任务会一直停在「排队中」）。

### 3.2 进程与模式

| 项 | 说明 |
| --- | --- |
| 网页端口 | `3939`，可用 `.env` 的 `PORT` 改；仅绑定本机 |
| AI 模式 | 由 `.env` 的 `AI_MODE` 决定（`dashscope` 走真实模型 / `mock` 走假数据） |
| 单实例 | 解析进程同时只跑一个，其余任务排队；进程号写在 `data/worker.lock` |
| 改配置后 | **必须重启解析进程**才生效（改 `.env` 后重启那个窗口即可） |

首版仅绑定本机地址，**不开放局域网或公网**（PRD 10.1）。

### 4.1 准备

1. 登录阿里云百炼控制台 → **API-KEY 管理** → 创建密钥。
2. 记录密钥所属区域：**中国站**（华北2 北京）或**国际站**（新加坡）。两站域名与密钥互不通用。
3. 在**业务空间**中确认已开通下列模型的调用权限：

   | 用途 | 模型 | 对应环境变量 |
   |---|---|---|
   | 音频识别 | `paraformer-realtime-v2` | `ASR_MODEL` |
   | 画面理解 | `qwen3-vl-plus` | `VISION_MODEL` |
   | 脚本整理（非思考模式） | `qwen-plus` | `ORGANIZE_MODEL` |

### 4.2 音频识别为何不是 PRD 原定的 `qwen3-asr-flash-filetrans`

PRD 10.5 确认的三模型中，音频识别为 `qwen3-asr-flash-filetrans`。该模型走 DashScope **异步任务**，
`file_urls` 只接受**公网可访问**的 HTTP(S) 地址。本机部署（127.0.0.1）无法提供公网地址，实测结论：

| 尝试的地址 | 结果 |
| --- | --- |
| `oss://dashscope-instant/.../audio.wav`（临时上传凭证上传后） | `InvalidParameter.MalformedURL` |
| `https://dashscope-file-mgr.oss-cn-beijing.aliyuncs.com/...`（同上，私有桶直链） | `InvalidParameter.MalformedURL` |

`dashscope-file-mgr` 临时桶只服务多模态对话类接口，**不是**给录音文件识别用的公网托管。
因此本机部署改走**实时语音识别 WebSocket**：允许直接推送本地音频二进制帧，无需公网地址，且返回句级时间戳。

选型对比（2026-09-12 实测，19.7 秒四句中文，句间 600ms 停顿，真值边界 180/4620、5060/9840、10240/15220、15660/19640 ms）：

| 模型 | 句数 | 时间戳结果 | 结论 |
| --- | --- | --- | --- |
| `paraformer-realtime-v2` | 4 | 与真值边界完全吻合 | **采用** |
| `fun-asr-realtime` | 3 | 第 2、3 句被合并，漏切 | 不采用 |
| `qwen3-asr-flash-realtime` | — | `ModelNotFound` | 不存在 |

推流速率 1x 与 4x 得到**完全相同**的时间戳，故默认 `ASR_PUSH_SPEED=4` 以缩短等待。

另外 `qwen3-asr-flash`（OpenAI 兼容同步接口）虽然支持 Base64 音频、本地可用，但**只返回整段文本、
不含任何时间戳**（annotations 仅有 emotion/language），无法支撑 16 列契约里每段的起止时间，故不采用。

**保留的切换开关**：`.env` 的 `ASR_TRANSPORT=filetrans` 可切回 `qwen3-asr-flash-filetrans`。
若将来具备公网存储能力（如自建 OSS + 签名 URL），改此开关即可，业务代码不动。

### 4.3 填入 `.env`

```env
DASHSCOPE_API_KEY="sk-xxxx"
# beijing  = 中国站 → https://dashscope.aliyuncs.com
# singapore = 国际站（新加坡）→ https://dashscope-intl.aliyuncs.com
DASHSCOPE_REGION="beijing"
VISION_MODEL="qwen3-vl-plus"
ORGANIZE_MODEL="qwen-plus"

ASR_TRANSPORT="realtime"
ASR_MODEL="paraformer-realtime-v2"
ASR_PUSH_SPEED="4"
ASR_MAX_SENTENCE_SILENCE="800"
ASR_LANGUAGE_HINTS="zh,en"
ASR_DIARIZATION="false"
```

调参提示：`ASR_MAX_SENTENCE_SILENCE` 偏小会把一句话切碎，偏大会把多句合并；`ASR_DIARIZATION=true`
会额外返回 `speakerId`（不自动等同主体或旁白，PRD 10.6）。

### 4.4 先自检，再切模式

```bash
npm run check:ai                        # 三模型最小调用，产生极少量费用
npm run check:ai -- --audio 你的素材.mp4  # 用真实语音验证句级时间戳与识别效果
npm run check:ai -- --skip-asr           # 只验文本与视觉模型
```

自检直接调用生产适配器（不是另写一份实现），因此「自检通过」等价于「解析进程里的真实调用链路可用」。
它会打印实际生效的区域与域名、密钥掩码、各模型耗时与估算费用，并在失败时给出排查方向。

自检通过后再切模式并**重启解析进程**：

```env
AI_MODE="dashscope"
```

### 4.5 必须重启解析进程

独立进程（`tsx src/worker/index.ts`）不会像 Next.js 那样自动加载 `.env`，
因此项目在 `src/lib/config.ts` 与 `src/lib/db.ts` 顶部显式调用 `loadDotEnv()`（`src/lib/load-env.ts`）。
只重启网页、不重启 `npm run worker`，会出现「网页显示 dashscope、实际仍在跑 mock」的静默不一致。

### 4.6 报价口径

`src/lib/config.ts` 的 `cfg.pricing` 为估算口径，价格核对日 2026-09-12、华北2（北京）档位，**实际以阿里云账单为准**：

| 项 | 单价 |
| --- | --- |
| `paraformer-realtime-v2` | 0.00024 元/秒 |
| `qwen3-vl-plus` | 按单次请求输入 tokens 分档：≤32k 为 1/10，≤128k 为 1.5/15，≤256k 为 3/30（元/百万 tokens，分别对应输入/输出） |
| `qwen-plus` | 输入 0.8、输出 2（元/百万 tokens） |

视觉模型按档位计价而非单一价：不分档会把长输入（9 张采样图可能超过 32k tokens）的费用算低。
每次调用的单价版本随 `ModelUsage.priceVersion` 落库，改价不会改写历史记录。

### 4.7 其他

- 密钥只保存在 `.env`，不下发浏览器、不写入 Excel、不进日志（PRD 11.2）。
- 三类适配器位于 `src/lib/ai/dashscope/`，供应商上传、推流、轮询、错误码与原始返回结构全部收敛在其中；
  业务页面、数据库与 Excel 不依赖供应商返回结构，替换模型不需要改业务代码。

### 4.8 换模型：不用重建 API Key，也不用单独充值

- **API Key 是账号/业务空间级凭证，不绑定模型。** 同一区域内换任何模型都用同一把 key，
  不需要在控制台逐个"开通"，也不产生新费用项。实测一把北京 key 直接调通
  `paraformer-realtime-v2` / `fun-asr-realtime` / `qwen-audio-3.0-asr-flash-streaming` /
  `qwen3-vl-plus` / `qwen3-vl-flash` / `qwen3.8-flash` / `qwen3.8-max` / `qwen3.7-plus` / `qwen3-max`。
- **只有换区域才需要新 key**：北京站与新加坡站密钥互不通用。
- `qwen3-asr-flash-realtime` 官方标注「部署范围：国际」，北京站调用必然 `ModelNotFound`
  （实测 0.4 秒失败）。这**不是**"没开通"，是该区域没有这个模型 —— 换模型前先确认区域部署。
- **充值**：按量付费，全模型共享账户余额，不需要为单个模型充值；
  但**免费额度按模型独立发放**（文本类约 100 万 tokens / 90 天，语音类 36,000 秒），
  换模型相当于换一份新额度，短期内可能反而不用额外充值。
- 换模型的操作只有两步：改 `.env` 里对应变量 → **重启解析进程**（见 4.5）。

| 音频识别 | **保持 `paraformer-realtime-v2`**（并开启 `word_timestamp_enabled`） | 唯一稳定切出句级边界的。官方"建议迁移到 Fun-ASR"面向实时字幕场景，不适用于需要逐句起止时间的本项目。**词级时间戳必须开启**：句级切分对连续口播会并出 60 秒长句，只能靠词边界再细分（详见 5.5） |
| 画面理解 | **可换 `qwen3-vl-flash`** | 同帧数、描述量级相当（还多认出测试卡上的数字 8→9），费用降到 1/6、耗时减半 |
| 脚本整理 | **可换 `qwen3.8-flash`** | 输出与 `qwen-plus` 一致，提速 41%，费用仅 +¥0.0004；且 `qwen-plus` 已被官方列入「旧版模型」 |

三项同时切换后，单条素材成本由约 **¥0.0234 降到约 ¥0.0100（-57%）**。

> **必须提醒**：验收用的是 `ffmpeg` 合成的**彩条测试图案，画面中没有人**。
> 因此本轮只验证了契约、切帧、时间戳、费用与耗时，**不能据此判断「妆造 / 情绪」的描述质量**。
> 换视觉模型前，请用真实人像素材再跑一次 `npm run bench:models -- --only=vision` 并请编导确认。

### 4.10 换模型时的兼容性注意

- **思考模式默认开启**：`qwen3.8-flash` / `qwen3.8-max` 即使传 `response_format: json_object`
  也默认走思考模式（返回带 `reasoning_tokens`）。实测 9 张图 `qwen3.8-max` 输出 8500 tokens、
  耗时 167 秒、费用 ¥0.40。适配器已显式传 `enable_thinking: false`（PRD 10.5 要求非思考模式）。
- **跨模型族字段名会漂移**：`qwen3-vl-*` 返回 `{"frames":[{"timeMs":…}]}`，
  `qwen3.8-*` 返回 `{"frame_details":[{"time":…}]}`，另有模型直接返回顶层数组。
  视觉适配器现已兼容「顶层数组 / `frames` / `frame_details`」结构、
  `timeMs` / `time_ms` / `time` / `timestamp` 时间字段，以及中文键名回退；
  **返回 0 帧时会抛出明确的 error 级问题**，而不是静默产出空白妆造/场景/情绪。
- **形式建议的键名同样会漂移**：实测 `qwen3-vl-plus` 曾返回
  `videoFormSuggestion/{isMontage,aiGeneratedIntervals}`，而约定键名是 `form/{mixedCut,aiIntervals}`。
  两者语义相反（`isMontage:true` 曾被映射成「混剪」，把真人实拍误判成混剪）。
  现已同时接受两套命名，且**两者都取不到时会给出 `VISION_FORM_CONTRACT_MISSING` 警告**，
  不会再静默退化成一个「看起来正常」的形式结论。
- **调提示词或换模型后，先跑一次 `npm run check:vision`**：它会打印解析后的形式判定与最终结论；
  设 `DASHSCOPE_DUMP_RAW=1` 还会把模型原始返回落盘到 `data/tmp/dashscope-raw/`，
  用于核对「模型实际按什么键名返回」——字段名错配过去是静默发生的，光看日志发现不了。
- **价格分档**：视觉模型按单次请求输入 tokens 分档计价，更换模型后若档位不同，
  需同步更新 `cfg.pricing` 并提升 `priceVersion`，否则费用估算会失真。

### 5.1 已实现的行为

- 完整业务链：链接录入 → **只接受可定位到单条素材的链接**（首页/列表页会被拒绝，不自动批量抓取）→
  登录态检查 → 失败原因准确提示 → **保留原链接** → 本地补传 → 缓存 → 媒体可读性校验 → 只有缓存成功才进入内容解析。
- 真实抓取：复用编导扫码登录一次的**专用会话**，无头打开素材页，三路捕获媒体地址
  （网络响应 / 接口 JSON / 页面 `video` 元素），再用三级下载兜底取回原文件：

  | 级别 | 手段 | 说明 |
  |---|---|---|
  | 1 | 带 cookie 流式直取 | 边下边写盘，不把整片读进内存；HLS 则用内置 ffmpeg 拉流合并 |
  | 2 | 页面自行触发的下载事件 | 少数素材页会自动触发下载，先接住 |
  | 3 | 点页面「下载」入口 + 接收下载事件 | 走浏览器自身登录态与自身下载逻辑，最耐页面改版 |

- 候选地址按证据打分排序并设下限。妙思素材页会同时加载**官网宣传小片与推荐位视频**，
  若「先出现算赢」会静默下错文件 —— 官方首页那几条 `home-v2-cards` 宣传片实测得分 -2 ~ -27，
  未达下限时不会硬下，而是走下载入口兜底或明确报失败。
- 未满足条件时任务会明确提示「抓取未启用 / 未找到登录会话 / 登录态已失效」，并引导本地补传，
  **不会伪装成获取成功**。
- **「抓到了另一条视频」的三道闸门（2026-09-16 修复，务必保留）**。此前出现过
  「粘什么链接都取回一段约 9 秒 / 300KB 的宣传片」：登录态失效时页面被弹回首页并弹出登录框，
  而登录墙正则只收「扫码登录 / 立即登录」这批词，**漏掉了弹窗自己的文案**
  （「微信扫一扫 / 免注册自动登录 / 登录即代表同意」），于是被判为「已登录」，
  接着在页面上挑媒体地址，把登录弹窗的装饰视频 `media/common/login-dialog-deco-video-*.mp4`
  当成了素材本体。现在三道闸门同时生效：

  | 闸门 | 判据 | 拦住的错误 |
  |---|---|---|
  | 登录墙 | `LOGIN_WALL_RE` 覆盖登录弹窗文案 | 不再把未登录判为已登录 |
  | 落点 | `landedReachesMaterial`：最终地址里必须还带着链接中的素材 id | 被弹回首页/别的素材时直接判 `MATERIAL_NOT_REACHED`，页面上的任何媒体地址都不当作结果 |
  | 地址与体积 | `SITE_ASSET_RE`（含 `login-dialog`、`media/common/`）+ `MIN_MEDIA_SCORE` | 站点装饰/宣传素材天然负分，无法通过下限 |

  再加一道**时长校验**：先取原网页标注的素材时长（`insight.durationSec`），
  逐个试下载候选后比对，明显不符就排除、换下一个候选；三级下载兜底产出的文件同样要过这一关。
  这一步专治「详情页同时挂着相关推荐，按地址证据下单却拿到别的视频」。
  拿不到时长判据（网页没给 / ffprobe 读不出）时放行，不否定已下载成功的候选。

  下限取 `MIN_MEDIA_SCORE=20`。**不能调高**：榜单素材本体走无扩展名签名直链，
  实测得分只有 44（无扩展名 6 + `video/mp4` 8 + 体积 ≥2MB 30），
  一度设成 50 导致正常素材全被判为「未发现可下载的媒体地址」。

### 5.2 原网页「视频分析」板块采集（人群分析 / 分镜或高光时序 / 创意标签）

三块内容不在页面 HTML 里，而来自详情接口
`POST /intelligent/api/v1/inspiration/ranking_detail/get`。字段映射（2026-09-15 实测）：

| 导出列 | 接口字段 | 说明 |
|---|---|---|
| 性别特征 | `label_info.core_gender` | 仅取「核心受众」，不并入投放定向倾向 |
| 年龄特征 | `label_info.core_age` | 同上 |
| 分镜/高光 title | `video_script_summary[].phase_name` | 有分镜用分镜阶段名；无分镜时取 `click_time_series` 点击峰值时刻（如 `00:03（点击峰值）`） |
| 创意标签 | `label_info` 其余 20 个键 | 英文键名本地映射为中文（如 `apply_gender` → 定向性别），全部内容拼接 |

**为什么不自己发请求**：妙思接口有 CSRF 校验，必须同时带上 `x-csrf-token`（取自 `csrf-cookie`）、
`x-trace-id`、`x-timestamp` 与前端 SDK 计算的 `x-sign`。实测在页面上下文里用 `fetch`/`XHR`
自行发请求（即使补齐上述全部请求头）一律返回 `{"code":221010,"message":"csrf check invalid"}`。
因此采集改为**收割页面自身已发出的接口响应**（`src/lib/sources/muse-insight.ts` 的
`attachMuseHarvest`，必须在 `page.goto` 之前挂上）：素材详情页渲染时会自行调用该接口，
其响应就含全部板块内容。这样既不依赖签名算法（改版也不易失效），也不额外增加请求。

- 硬限制：板块只对灵感广场榜单内素材提供。接口返回空骨架时，相关字段按需求**标记为空**
  并在「板块说明」里写明原因（区分「不在榜单范围」与「未读到详情数据」）。
- 采集失败不影响取视频：`insight` 为空值并带原因，主链路照常完成。

### 5.5 语音识别粒度：长句必须细分（2026-09-16 修复）

**现象**：分出的第一段含一大段文字，且与后面几段大量重合。

**根因**（实测定位，不是分段逻辑的问题）：`paraformer-realtime-v2` 的句切分按静音工作，
而信息流广告多为**连续口播 + BGM**，几乎没有超过阈值的停顿，于是服务端把开头整段并成一句：

| 素材 | 识别片段 | 最长片段 |
|---|---|---|
| 134580000001（69.8s） | 修复前 **2 段** | `0–60.02s`（425 字） |
| 134580000003（70.4s） | 修复前 2 段 | 约 59s |
| 134580000002（123s） | 修复前 4 段 | `2.56–61.96s` |

**对照实验**（确认变量）：推流 1x 与 4x **结果完全一致**（推流速度无关）；
把 `ASR_MAX_SENTENCE_SILENCE` 从 800ms 降到 400ms，片段数 2 → 8，但仍有 37 秒的长片段
（说明该素材确实没有长停顿，调参**不能根治**）。

**修复**：开启 `word_timestamp_enabled`，在**词边界**上按句末标点把长句细分为「语块」，
时间为该语块首末词的真实时间。关键保真依据：**「词文本 + 词标点」拼接与识别原文逐字一致**
（实测 425 字完全一致），拼不回原文时**不切**——宁可粒度粗，也不用错误的切点破坏原文。

效果：同一条素材的识别片段 **2 → 16 个**（最长 9 秒），时间精确到词级。

### 5.6 原视频标题与任务标题（2026-09-16 第三轮）

工作台里有两个容易混淆的「标题」，**分开保存、职责不同**：

| 字段 | 位置 | 取值 | 可改 |
|---|---|---|---|
| **原视频标题** | 「视频分析」最上方（导出为第 1 列） | 本地导入 = **原文件的文件名**；链接导入 = **链接对应网页的标题** | ❌ 保留原样，人工改标题不影响它 |
| 标题 | 「任务信息」 | 人工填写优先 → 自动获取 → 未提供（`titleSource` 记录来源） | ✅ 输入框 + 保存标题；改过即 `MANUAL`，重新解析不会覆盖 |

**妙思标题节点的定位（实测，勿改回旧写法）**：素材详情页没有 `h1/h2`，站点
`document.title` 是「腾讯妙思 - 营销内容AIGC创作平台」，所以旧写法（找 `assetName`/`h1`/`h2`
再退到站点标题）在真实素材上**一律返回 undefined**，表现为标题长期「未提供」。实测确认：
素材标题是页面上**唯一**一个「计算字号 20px + 字重 500 + 内联字体为 PingFangSC」的节点；
同页的指标数字（`4W+`、`1%-3%`、`22.78s`）字号字重相同但字体是 `ODNumber`，必须排除。
`readMaterialTitle()` 按「ellipsis 优先 → 非 ODNumber → 旧选择器 → document.title」的顺序取第一个命中值，
取不到就返回 undefined，**不用站点名冒充**。

> 实现注意：该探测以**字符串形式**传给 `page.evaluate`。本项目用 tsx 运行，函数体内会被注入
> `__name` 辅助变量，在页面上下文里会报 `__name is not defined`。

存量记录的「原视频标题」用 `npm run backfill:title` 回填（本地导入直接取 `fileName`；
链接导入需要重新打开素材页，加 `--fetch` 才执行，不调用模型、不产生模型费用）。

## 6 脚本处理新逻辑（2026-09-15 需求方确认，2026-09-16 修订）

针对「脚本整理」环节的整体改造：

2. **转写文案切分并打标签** → 人设 / 痛点 / 干货（解决方案）/ 营销内容（产品介绍）/ 福利，
   每段只能有一个标签、不得重复标记。
3. **表头改为标签列** → 以六类标签作表头，用对应标签的**转写原文**填充，

4. **视频分析栏与结构删减** → 原表头的妆造 / 画面场景 / 情绪 / 形式 / 视频链接统一划入「视频分析」栏；
   检测到形式为混剪时妆造 / 画面场景 / 情绪全部留空且只标注一次；删除原表头的序号时间 / 文案 / 旁白；
   脚本表格只保留一行。

**2026-09-16 第二轮修订（按需求方口径）**：

- **修复「段落内容重复」**：根因不在分段逻辑，而在语音识别的句切分——带 BGM 的连续口播会被
  服务端并成一条 60 秒的巨型片段，模型无法在片段内部再切分，于是首段吞掉整段文案、

警告（`normalizeTag()`），保证「每段必有且只有一个标签、不丢段」。

### 6.3 原文保真与段落划分兜底（重要）

需求红线是「用转写原文填充，不能对原文作更改」，另一条是「**每段内容不应重复**」。
两条都不能靠提示词约束，必须由程序保证。

**（1）原文由程序回填。** 实测在真实素材（`134580000002`，124 秒）上，整理模型即使被明确要求
「忠实原话」，仍然把 6 段里的 5 段改写/补写。因此流水线在保真校验**之前**执行确定性回填：
`copyText` 一律改为「该段引用的原始语音片段」的原文拼接，模型对文案的改写一律丢弃并留痕。

**（2）段落划分由程序重建。** 实测整理模型会给出**相互重叠的引用**——70 秒素材里第 1 段引用了
横跨 `0–60s` 的整块片段，第 2~5 段又重复引用它。旧实现在「引用的片段已被前段占用」时会
**原样保留模型写的文案**，于是结果就是「第一段一大段文字、后面几段与它大量重合」。

现在由 `partitionSegments()`（`src/lib/validate.ts`）按原始语音片段重建划分，规则：

1. **一个片段只归属一段**：按段落顺序「先引用先归属」，重复引用只记问题、不重复归属；
2. **不丢内容**：模型没引用到的片段，按时间就近归入覆盖它的段落（`UTTERANCE_ASSIGNED` 留痕）；
3. **时间不再信模型**：段落起止由所归属片段的真实时间推导（实测模型给的时间与实际引用范围
   能差 15 秒以上，旧数据里出现过「标称 0–13.9s、内容却到 27.9s」）；
4. **重复段直接丢弃**：一段若没有任何独立片段（内容已全部属于其他段），整段丢弃并留痕，
   绝不留重复文案；
5. 划分后按推导出的真实时间重排，保证段落顺序与原视频一致。

**验收口径**：第 2 段起，每段的「6 字片段与前面段落重合的比例」应 < 50%；
`verify:muse` 会把逐段重合度打印出来并断言。同时「脚本文案 = 各段文案按序拼接」也是一条
不重不漏的强校验（脚本会自动比对）。

处理过程中可能出现的问题码（均为 warn，不阻断出结果）：

| 问题码 | 级别 | 含义 |
|---|---|---|
| `TEXT_REPAIRED` | warn | 模型文案与引用原文不一致，已按原文回填 |
| `DUPLICATE_UTTERANCE` | warn | 片段被重复引用，已按首次归属处理 |
| `UNKNOWN_UTTERANCE_REF` | warn | 引用了不存在的片段 id，已忽略 |
| `UTTERANCE_ASSIGNED` | warn | 有片段未被任何段落引用，已按时间归入相邻段 |
| `SEGMENT_DROPPED` | warn | 该段没有任何独立片段（与前面内容重复），已丢弃 |
| `ORGANIZE_EMPTY` | warn | 模型未返回段落，已按语块逐块保留文案 |
| `ASR_COARSE_SENTENCE` | warn | 有超长识别片段且无词级时间戳，无法细分，需人工核对 |
| `TAG_INVALID` | warn | 标签越界/缺失，已归入「其他」 |

`checkTranscriptFidelity()` 保留为兜底安全网（划分后 `REWRITTEN` / `MISSING_UTTERANCE` 应为 0）。
模型角色因此收敛为：**分段 + 打标签 + 妆造 / 情绪**，不承担文案改写，也不承担「保证不重不漏」。

### 6.4 形式判定与混剪分支

**形式取值（2026-09-16 第四轮收敛为 4 项）**：`混剪` / `AI数字人` / `真人` / `其他`。
判定顺序与阈值（`src/lib/classification.ts`，阈值可配）：

| 顺序 | 条件 | 结论 |
| --- | --- | --- |
| 1 | 画面无连贯主体、由多个独立素材拼接 | 混剪 |
| 2 | AI 画面时长占比 ≥ `AI_VIDEO_RATIO_THRESHOLD`（默认 **0.75**） | AI数字人 |
| 3 | 真人内容占比 ≥ `REAL_PERSON_RATIO_THRESHOLD`（默认 **0.75**），即 AI 占比 ≤ 25% | 真人 |
| 4 | 其余（25%~75% 的中间带） | 其他 |

- 阈值含等号：恰好 75% 归 `AI数字人`，恰好 75% 真人内容归 `真人`。
- 模型无法可靠估计占比时**仍落「其他」**，但**不编造比例**（`ratioEstimated=false`），
  并在依据字段写明「模型无法可靠估计 AI 画面区间」，便于编导识别需复看的记录。
- 原取值 `ai视频` / `有ai片段` / `真人口播` / `真人访谈` / `其他及简短说明` / `待复核` 已全部取消，
  存量记录用 `npm run migrate:form`（先 `--` 试运行，再加 `--apply`）按上表回填。
- 人工纠正入口仍在工作台「任务信息 → 形式」下拉，只提供上述 4 项；
  接口 `/api/videos/[id]/classification` 会对旧取值返回 400。

形式判定为「混剪」时**不再停止解析**：文案照常分段打标签，只是妆造 / 画面场景 / 情绪三项留空
（只标注一次、不做任何推断）。会写入一条 `MIXED_CUT_PARTIAL` 说明供编导知悉。

## 10 已知限制与说明

- 妙思真实抓取已启用并验证通过（见第 5 节）；三模型真实调用已跑通（见第 8 节）。
  妙思资产库（成品库/原料库）抓取尚未验证，原因见第 5.7 节。
- **音频识别与 PRD 10.5 原定模型不一致**：`qwen3-asr-flash-filetrans` 要求公网可访问的文件地址，
  本机部署无法满足，已改走 `paraformer-realtime-v2`（WebSocket 直推本地音频）。原因与实测对比见第 4.2 节，
  并提供 `ASR_TRANSPORT` 开关可切回。**这是需要与需求方确认的一处偏离。**
- 音频识别为**实时推流**，处理耗时与音频时长同阶（当前 4x 倍速下约 0.25~0.9 倍）。
  长素材的等待时间明显长于异步批处理，`STAGE_TIMEOUT_MS` 已按上限 30 分钟素材放宽到 15 分钟。
- `data/tmp` 下的 PCM 中间文件在每次识别结束后删除；进程被强杀时可能残留，可安全手动清理。
- 妙思「基本信息」板块**只对灵感广场榜单内素材提供**：接口对该范围外的素材返回空骨架，
  此时性别/年龄/分镜/创意标签按需求标记为空并写明原因，不是抓取故障；
  也无法通过自行发请求绕过（妙思接口有 CSRF 校验，详见 5.2 节）。
- 六类标签的**分段边界由整理模型决定**，同一素材两次运行的分段数与标签分布可能不同（无随机种子）；
  但「不重不漏」由程序保证，不受模型随机性影响（见 6.3）。
  文案本身由于程序级原文回填始终与转写原文一致，但「一段一个标签」的归类质量仍需编导在复核界面确认。
- Mock 模式下的指纹不进入判分：验收用的素材是 `ffmpeg` 生成的合成画面与正弦音轨，只验证流程与格式，不用于评估识别质量。
- `data/` 目录（数据库、媒体缓存、画面取样帧、导出）默认保留至用户删除，删除视频会同步清理其版本、取样帧、媒体与相关合并导出文件。
- 升级 Next.js / Prisma 前请先执行 `npm run db:push` 并保留 `data/app.db` 的可恢复副本（PRD 10.3）。
