# 信息流编导工作台（本地部署版）

面向微信视频号信息流 / 短视频编导的本地工作台：把「看片扒词 → 拆分镜 → 打标签 → 出表归档」这条手工链路，收敛成一条在本机自动跑完的流水线，并可从结果继续接上「按自有 IP 改写 → 数字人成片」。全部环节在本机完成，素材、转写与账号会话都不出本机。

两条链路，互不影响：

1. **脚本还原** —— 把参考视频还原为**可复核、可编辑、可供拍摄团队使用的脚本**；不改写为自有 IP 内容、不润色原话、不提取字幕。
2. **个性化改写**（见第 10 节）—— 用自有 IP 把同一条内容讲出来：以已复核的参考脚本为**结构骨架**，注入 IP 资料包生成多个版本供编导比较选定，再送数字人平台出片。这一条是**创作**，与上一条的「一字不改」是两套独立逻辑。

## 2 技术栈

| 层次 | 技术 |
| --- | --- |
| 网页与后端 API | Next.js 14（App Router）+ TypeScript |
| 解析进程 | Node.js + TypeScript 独立进程（`tsx src/worker/index.ts`） |
| 数据访问 / 本地数据库 | Prisma + SQLite（`data/app.db`，WAL 模式） |
| 媒体处理 | FFmpeg（随项目安装 `ffmpeg-static` / `ffprobe-static`，**不要求主机预装**） |
| 妙思抓取 | Playwright（随项目安装 `playwright` + chromium；缺失时降级为保留链接 + 本地补传） |
| 数字人出片 | 鲲之益 AIGC，同样走 Playwright；官方 API 未确认，已抽象为 `AvatarAdapter` 接口便于日后替换 |
| IP 资料包解析 | 自实现 `src/lib/rewrite/docx.ts`（`node:zlib` 解 ZIP + 查 EOCD），**零新增依赖** |
| 音频识别 | WebSocket 全双工（Node 内置 `WebSocket`，**不新增依赖**） |
| .env 加载 | 自实现 `src/lib/load-env.ts`（独立进程不自动读取 `.env`，见 4.5） |

网页与解析进程共享 `src/lib` 下的字段类型与统一解析结果结构。

## 3 快速开始

```bash
cd video-script-agent
npm install
cp .env.example .env          # Windows: copy .env.example .env
npm run setup                 # prisma generate + db push + seed 账号
npm run make:test-media       # 可选：生成自备测试素材到 data/samples
npm run dev                   # 同时启动网页（3939）与解析进程
```

访问 http://127.0.0.1:3939。初始账号在部署时配置，仓库内**不提供任何口令**：

| 账号 | 角色 |
| --- | --- |
| `maintainer` | 部署维护人员 |
| `editor` / `editor2` | 编导（`editor2` 仅用于验证多账号隔离） |

首次部署前先在 `.env` 中设置 `SEED_MAINTAINER_PASSWORD`、`SEED_EDITOR_PASSWORD`、
`SEED_EDITOR2_PASSWORD` 再 `npm run db:seed`；未设置时种子脚本会使用占位口令并打印提醒，
**该占位口令仅供本地跑通，部署前必须替换**。分开启动用 `npm run dev:web` / `npm run worker`。

### 3.1 日常启动（不需要命令行）

Windows 下项目根目录两个脚本，**双击即可**：

| 脚本 | 作用 |
| --- | --- |
| `start-workbench.bat` | 启动网页（3939）+ 解析进程，等端口就绪后自动打开浏览器 |
| `stop-workbench.bat` | 关闭上述窗口、按 `data/worker.lock` 结束解析进程、释放端口 |

- 弹出的命令行窗口是两者的容器，**关掉它（或 Ctrl+C）即全部停止**。
- 网页刚起来就报错（构建缓存 `.next` 损坏）时，跑 `start-workbench.bat clean` 再启动。
- 只做查看 / 编辑 / 导出时可只开网页；但没有解析进程就**不能提交新视频**（任务一直停在「排队中」）。

### 3.2 进程与模式

| 项 | 说明 |
| --- | --- |
| 网页端口 | `3939`，可用 `.env` 的 `PORT` 改；仅绑定本机，不开放局域网或公网 |
| AI 模式 | 由 `.env` 的 `AI_MODE` 决定（`dashscope` 真实模型 / `mock` 假数据） |
| 单实例 | 解析进程同时只跑一个，其余排队；进程号写在 `data/worker.lock` |
| 数字人进程 | **独立进程与独立锁**（`npm run worker:avatar`），长等待不占用视频分析队列；`AVATAR_ADAPTER=mock` 时可不启动。`assist` 模式会弹出**可见的浏览器窗口**（需桌面环境） |
| 改配置后 | **必须重启对应进程**才生效 |

## 4 切换到真实模型（阿里云百炼）

### 4.1 准备

1. 登录阿里云百炼控制台 → **API-KEY 管理** → 创建密钥。
2. 记录密钥所属区域：**中国站**（华北2 北京）或**国际站**（新加坡）。两站域名与密钥互不通用。
3. 在**业务空间**中确认已开通下列模型的调用权限：

   | 用途 | 模型 | 对应环境变量 |
   |---|---|---|
   | 音频识别 | `paraformer-realtime-v2` | `ASR_MODEL` |
   | 画面理解 | `qwen3-vl-plus` | `VISION_MODEL` |
   | 脚本整理（非思考模式） | `qwen3.8-flash` | `ORGANIZE_MODEL` |

### 4.2 音频识别的选型说明

方案原定的 `qwen3-asr-flash-filetrans` 走 DashScope **异步任务**，`file_urls` 只接受**公网可访问**的
HTTP(S) 地址，本机部署无法满足（实测临时上传凭证与私有桶直链均返回 `InvalidParameter.MalformedURL`）。
因此改走**实时语音识别 WebSocket**：可直接推送本地音频二进制帧，无需公网地址，且返回句级时间戳。
同素材实测对比中，`paraformer-realtime-v2` 是唯一稳定切出句级边界、与真实停顿完全吻合的模型，故采用；
推流 1x 与 4x 结果完全相同，默认 `ASR_PUSH_SPEED=4` 以缩短等待。

**保留的切换开关**：`.env` 的 `ASR_TRANSPORT=filetrans` 可切回异步方案；将来具备公网存储能力
（如自建 OSS + 签名 URL）时改此开关即可，业务代码不动。

### 4.3 填入 `.env`

```env
DASHSCOPE_API_KEY="sk-xxxx"
# beijing  = 中国站 → https://dashscope.aliyuncs.com
# singapore = 国际站（新加坡）→ https://dashscope-intl.aliyuncs.com
DASHSCOPE_REGION="beijing"
VISION_MODEL="qwen3-vl-plus"
ORGANIZE_MODEL="qwen3.8-flash"

ASR_TRANSPORT="realtime"
ASR_MODEL="paraformer-realtime-v2"
ASR_PUSH_SPEED="4"
ASR_MAX_SENTENCE_SILENCE="800"
ASR_LANGUAGE_HINTS="zh,en"
ASR_DIARIZATION="false"
```

调参提示：`ASR_MAX_SENTENCE_SILENCE` 偏小会把一句话切碎，偏大会把多句合并；`ASR_DIARIZATION=true`
会额外返回 `speakerId`（不自动等同主体或旁白）。

### 4.4 先自检，再切模式

```bash
npm run check:ai                        # 三模型最小调用，产生极少量费用
npm run check:ai -- --audio 你的素材.mp4  # 用真实语音验证句级时间戳与识别效果
npm run check:ai -- --skip-asr           # 只验文本与视觉模型
```

自检直接调用生产适配器（不是另写一份实现），因此「自检通过」等价于「解析进程里的真实调用链路可用」；
它会打印实际生效的区域与域名、密钥掩码、各模型耗时与估算费用，失败时给出排查方向。
自检通过后再切 `AI_MODE="dashscope"` 并**重启解析进程**。

### 4.5 必须重启解析进程

独立进程不会像 Next.js 那样自动加载 `.env`，因此项目在 `src/lib/config.ts` 与 `src/lib/db.ts`
顶部显式调用 `loadDotEnv()`。只重启网页、不重启 `npm run worker`，会出现
「网页显示 dashscope、实际仍在跑 mock」的静默不一致。

### 4.6 报价口径

`src/lib/config.ts` 的 `cfg.pricing` 为**估算口径**，实际以阿里云账单为准：

| 项 | 单价 |
| --- | --- |
| 音频识别 | 0.00024 元/秒 |
| 画面理解 | 按单次请求输入 tokens 分档：≤32k 为 1/10，≤128k 为 1.5/15，≤256k 为 3/30（元/百万 tokens，分别对应输入 / 输出） |
| 文本类（整理 / 改写） | `qwen3.8-flash` 输入 0.8、输出 2.7（元/百万 tokens） |

视觉模型按档位计价而非单一价：不分档会把长输入（9 张采样图可能超过 32k tokens）的费用算低。
每次调用的单价版本随 `ModelUsage.priceVersion` 落库，改价不会改写历史记录。

### 4.7 其他

- 密钥只保存在 `.env`，不下发浏览器、不写入 Excel、不进日志。
- 三类适配器位于 `src/lib/ai/dashscope/`，上传、推流、轮询、错误码与原始返回结构全部收敛在其中；
  业务页面、数据库与 Excel 不依赖供应商返回结构，**替换模型不需要改业务代码**。

### 4.8 换模型：不用重建 API Key

**API Key 是账号 / 业务空间级凭证，不绑定模型**：同一区域内换任何模型都用同一把 key，不需要逐个
「开通」。**只有换区域才需要新 key**（北京站与新加坡站互不通用）。模型存在**区域部署差异**：某区域
没有该模型时会直接 `ModelNotFound`，这**不是**「没开通」，换模型前先确认区域部署。按量付费、全模型
共享账户余额，但**免费额度按模型独立发放**。换模型只需两步：改 `.env` 对应变量 → **重启解析进程**。

### 4.9 模型横向对比（`npm run bench:models`）

用**同一份素材、同一批采样帧**跑完三大需求的所有候选模型，输出逐句时间戳、逐帧描述、原文保真校验
与估算费用；只读，不写库、不改 `.env`。支持 `--only=`、`--file`、`--frames` 参数。

**选型结论（均为实测对比得出）**：

| 需求 | 建议 | 理由 |
| --- | --- | --- |
| 音频识别 | **保持 `paraformer-realtime-v2`**，并开启 `word_timestamp_enabled` | 唯一稳定切出句级边界的模型。**词级时间戳必须开启**：句级切分对连续口播会并出 60 秒长句，只能靠词边界再细分（见 5.5） |
| 画面理解 | **可换 `qwen3-vl-flash`** | 同帧数、描述量级相当，费用降到约 1/6、耗时减半 |
| 脚本整理 | **可换 `qwen3.8-flash`** | 输出与旧模型一致、提速明显，且旧模型已被官方列入「旧版模型」 |

三项同时切换后，单条素材成本由约 **¥0.023 降到约 ¥0.010**。

> **必须提醒**：验收用的是合成的彩条测试图案，**画面中没有人**，因此只验证了契约、切帧、时间戳、
> 费用与耗时，**不能据此判断「妆造 / 情绪」的描述质量**。换视觉模型前请用真实人像素材再跑一次
> `npm run bench:models -- --only=vision` 并请编导确认。

### 4.10 换模型时的兼容性注意

- **思考模式默认开启**：`qwen3.8-*` 即使传 `json_object` 也走思考模式（多返回 `reasoning_tokens`），
  适配器已显式传 `enable_thinking: false`。
- **跨模型族字段名会漂移**：视觉返回结构（`frames` / `frame_details` / 顶层数组）与时间字段名在不同
  模型族间不同，已全部兼容并做中文键名回退；**返回 0 帧时抛明确 error**，不静默产出空白结果。
  形式建议的键名同样会漂移且**语义相反**（误判会把真人实拍认成混剪）——现已同时接受两套命名，
  都取不到时给出 `VISION_FORM_CONTRACT_MISSING` 警告，不再静默退化成一个「看起来正常」的结论。
- **调提示词或换模型后先跑 `npm run check:vision`**；设 `DASHSCOPE_DUMP_RAW=1` 可把原始返回落盘，
  用于核对模型实际按什么键名返回（字段名错配过去是静默发生的，光看日志发现不了）。
- **价格分档**：视觉按输入 tokens 分档计价，换模型后档位不同需同步更新 `cfg.pricing`
  并提升 `priceVersion`，否则费用估算失真。

## 5 腾讯妙思真实抓取（admuse.qq.com）

> **脱敏说明**：本文出现的妙思素材 ID（形如 `1345800000xx`）均为**占位符**，仅用于示意地址格式与
> 验证结论，不代表任何真实业务素材。仓库内不含账号口令、抓取会话或媒体文件。

### 5.1 已实现的行为

- 完整业务链：链接录入 → **只接受可定位到单条素材的链接**（首页 / 列表页会被拒绝，不自动批量抓取）
  → 登录态检查 → 失败原因准确提示 → **保留原链接** → 本地补传 → 缓存 → 媒体可读性校验
  → 只有缓存成功才进入内容解析。
- 无头打开素材页，**三路捕获**媒体地址（网络响应 / 接口 JSON / 页面 `video` 元素），再用**三级下载
  兜底**取回原文件：① 带 cookie 流式直取（HLS 用内置 ffmpeg 拉流合并）→ ② 接住页面自行触发的
  下载事件 → ③ 点页面「下载」入口、走浏览器自身登录态与下载逻辑（最耐页面改版）。
- **候选地址按证据打分排序并设下限**：素材页会同时加载官网宣传小片与推荐位视频，若「先出现算赢」
  会静默下错文件。未达下限不硬下，改走下载入口兜底或明确报失败。下限 `MIN_MEDIA_SCORE=20`
  **不能调高** —— 榜单素材本体走无扩展名签名直链，实测得分只有 44。
- **防「抓到了另一条视频」**：登录态失效时页面会被弹回首页并弹出登录框，若登录墙正则漏掉弹窗
  自己的文案，就会把登录弹窗的装饰视频当成素材本体。现在同时设三道判据：**登录墙**正则覆盖弹窗
  文案；**落点**必须仍带着链接中的素材 id（否则判 `MATERIAL_NOT_REACHED`，页面上的媒体地址一律
  不采纳）；**站点装饰 / 宣传素材**（含 `login-dialog`、`media/common/`）天然负分、无法过下限。
  另加**时长校验**：与网页标注时长明显不符就换下一个候选（判据缺失时放行，不否定已下载成功的候选）。
- 未满足条件时明确提示「抓取未启用 / 未找到登录会话 / 登录态已失效」并引导本地补传，
  **不会伪装成获取成功**。

### 5.2 原网页「视频分析」板块采集

三块内容不在页面 HTML 里，而来自详情接口
`POST /intelligent/api/v1/inspiration/ranking_detail/get`，字段映射如下：

| 导出列 | 接口字段 |
|---|---|
| 性别 / 年龄特征 | `label_info.core_gender` / `core_age`（仅取「核心受众」，不并入投放定向倾向） |
| 分镜 / 高光 title | `video_script_summary[].phase_name`；无分镜时取点击峰值时刻 |
| 创意标签 | `label_info` 其余键，英文键名本地映射为中文后拼接 |

**为什么不自己发请求**：接口有 CSRF 校验，必须同时带上 `x-csrf-token`、`x-trace-id`、`x-timestamp`
与前端 SDK 计算的 `x-sign`；实测在页面上下文里自行发请求（即使补齐全部请求头）一律返回
`csrf check invalid`。因此改为**收割页面自身已发出的接口响应**（`attachMuseHarvest`，必须在
`page.goto` **之前**挂上）：详情页渲染时会自行调用该接口，响应即含全部板块内容。这样既不依赖
签名算法（改版也不易失效），也不额外增加请求。

- 硬限制：板块只对灵感广场榜单内素材提供；接口返回空骨架时相关字段**标记为空**并写明原因
  （区分「不在榜单范围」与「未读到详情数据」）。
- 采集失败不影响取视频：`insight` 为空值并带原因，主链路照常完成。

### 5.3 启用步骤

会话**按人隔离**：每个编导用自己的腾讯妙思账号扫码，抓取时用**任务归属人**自己的会话；
编导之间不互相顶账号，代价是扫码一次只能一个人（同时要扫就排队）。

**推荐做法**：登录工作台后什么都不用点 —— 页面自动检查你的妙思登录态，失效 / 未登录时
**自动弹出二维码**，微信扫一下即可；不想现在扫可点「稍后再说」，之后页头红色提示栏会一直挂着提醒。
也可在「我的妙思会话」页手动扫码；已是登录态而想**换一个微信号**时点「更换账号登录」。

```bash
npm run muse:login                     # 备选：打开浏览器扫码登录一次 → 自动识别并保存会话
npm run muse:login -- --user=editor    # 给指定账号登录（默认给维护人员）
npm run muse:migrate                   # 一次性：把旧的全局会话复制到维护人员名下（幂等，不覆盖）
```

网页版与命令行版走**同一份实现**，只有「有头 / 无头」的区别。登录成功后设置开关并
**重启解析进程**：

```env
MUSE_FETCH_ENABLED="true"
```

⚠️ `MUSE_FETCH_ENABLED` 是**进程启动时**读取的，改了必须重启解析进程；而**仅重新扫码登录不需要重启**
—— 每次抓取都会重新读取会话文件。会话按人落在 `data/muse-session/users/<userId>/state.json`，
只存在本机。浏览器运行时也随项目安装（`playwright` + `npx playwright install chromium`），
不要求主机另装。

### 5.3.1 登录态失效的预警与自查

**要解决的问题**：会话过期后用户仍能提交链接，任务一路跑到保存阶段才失败，最后只看到
「主机视频副本不可用」，完全看不出真因是登录态过期。现在：

- **页头常驻提示栏**：自己的登录态失效时出现，写清影响面（链接抓取会失败，脚本文案与来源信息
  不受影响），附「去扫码登录」按钮（**人人可点** —— 每个人都给自己扫）。可临时收起，
  **收起只对当下这一次失效有效**，登录态一旦变化就重新出现。
- **抓取前置拦截**：已确知失效时不再白开一次浏览器。
- **探测按成本分层**，能零成本定罪就不开浏览器：抓取结果本身（免费）→ 会话文件缺失 / 无 cookie
  （免费）→ **会话 cookie 自带的到期时间**（免费且精确）→ 无头浏览器读页面文案（约 4 秒）。
  取「最晚的一条 cookie」判定 —— 只要还有任一条未到期就不敢断言失效，否则会误拦本来能成功的抓取。
- 结论有效期由 `MUSE_HEALTH_TTL_MS` 控制（默认 15 分钟）；探测只在「打开工作台且结论已过期」时
  执行一次，由**解析进程独占执行**（Chromium 单一所有者），web 只读结论文件，请求不会被阻塞。
- **实测会话寿命约 1.4 天，重扫是常态运维，不是异常处置。**

**为什么不做轻量 HTTP 探测**：接口有 CSRF 校验（见 5.2），唯一可信的判据是「真实浏览器渲染后读
页面文案」，本项目**不伪造请求**。**换微信号必须走「强制登录」**：已登录时页面上没有登录入口，
点不出二维码；强制登录不带本地登录态启动，必然看到登录入口，且只在扫码成功后才覆盖会话文件。

### 5.4 排查命令与端到端验证

```bash
npm run muse:check                        # 会话是否仍有效（零成本判据优先）
npm run muse:probe -- "<链接>"             # 诊断单条素材：登录态、候选地址与得分、截图
npm run muse:probe -- "<链接>" --download  # 再跑一遍正式适配器，验证真实下载
npm run muse:probe -- --nav                # 导航路由发现，摸清资产 / 成品库的真实地址
npm run muse:insight -- "<链接>"           # 只跑「视频分析」板块采集，不下视频、不花模型费
npm run muse:detail -- --scan=10           # 统计板块有值率
npm run diag:segment -- --latest           # 分段链路诊断：片段边界 → 模型分段 → 划分结果 → 逐段重复度
npm run backfill:title                     # 回填「原视频标题」
npm run backfill:title -- --fetch          # 连链接导入一起回填（重开素材页读网页标题，不花模型费）
npm run verify:muse -- "<链接>"            # 端到端：只给链接 → 真实抓取 → 真实模型 → 两种导出
npm run verify:muse-session                # 登录态提示栏 + 会话页 + 接口契约 + 收起语义
npm run verify:muse-login                  # 网页扫码链路：二维码取回 / 取消 / 不污染状态
npm run verify:muse-ttl                    # 探测节流：结论新鲜时不得重复探测
```

后三个需要**工作台在运行**，且必须用**真实浏览器**断言 —— 工作台是客户端组件，SSR 只吐加载壳，
用 curl 检查会假 PASS。三者都不需要真实模型，也不消耗妙思额度。`diag:segment` 是排查
「段落重复 / 首段过长 / 时间与内容对不上」的第一手段，只跑三段链路、不写业务库。
`muse:probe` 与解析进程共用同一套捕获与判定，因此诊断结论可直接外推为正式抓取的行为。

**拿什么链接做测试**：妙思是 hash 路由 SPA，「单条素材详情页」地址形如
`https://admuse.qq.com/#/idea/detail/video/<数字ID>`；首页、列表页这类无法定位到单条素材的链接会被
**明确拒绝**，这是设计如此，不是故障。若当前账号未关联腾讯投放账户，资产库 / 成品库 / 原料库会是
空的并给出提示，此时用**灵感广场的素材详情页**即可完成真实业务验证，链路完全一致。

### 5.5 语音识别粒度：长句必须细分

**现象**：分出的第一段含一大段文字，且与后面几段大量重合。

**根因**：句切分按静音工作，而信息流广告多为**连续口播 + BGM**，几乎没有超过阈值的停顿，于是服务端
把开头整段并成一句（实测出现 `0–60.02s`、425 字的巨型片段）；模型无法在这个原子片段内部再切分，
结果就是首段吞掉整段文案、后续段落又大量与之重合。调参**不能根治**（推流倍速无关；静音阈值从
800ms 降到 400ms 后片段数增加，但该素材确实没有长停顿，仍有 37 秒长片段）。

**修复**：开启 `word_timestamp_enabled`，在**词边界**上按句末标点把长句细分为「语块」，时间为该语块
首末词的真实时间。关键保真依据：**「词文本 + 词标点」拼接与识别原文逐字一致**，拼不回原文时
**不切** —— 宁可粒度粗，也不用错误的切点破坏原文。效果：同一条素材的识别片段由 2 个增至 16 个，
时间精确到词级。

### 5.6 原视频标题与任务标题

| 字段 | 位置 | 取值 | 可改 |
|---|---|---|---|
| **原视频标题** | 「视频分析」最上方（导出第 1 列） | 本地导入 = **原文件名**；链接导入 = **对应网页标题** | 否。人工改标题不影响它 |
| 标题 | 「任务信息」 | 人工填写优先 → 自动获取 → 未提供 | 是。改过即 `MANUAL`，重新解析不覆盖 |

**妙思标题节点的定位（实测，勿改回旧写法）**：素材详情页没有 `h1/h2`，`document.title` 是营销平台名，
所以旧写法在真实素材上一律返回空、表现为标题长期「未提供」。实测素材标题是页面上**唯一**一个
「计算字号 20px + 字重 500 + 内联字体 PingFangSC」的节点（同页指标数字字号字重相同但字体不同，
必须排除）；取不到就返回空，**不用站点名冒充**。

> 实现注意：该探测以**字符串形式**传给 `page.evaluate` —— 本项目用 tsx 运行，函数体会被注入
> `__name` 辅助变量在页面上下文报错；且字符串会被当作**表达式**求值，必须写成 IIFE。

存量记录用 `npm run backfill:title` 回填（链接导入需加 `--fetch`，不调用模型、不产生模型费用）。

### 5.7 尚未验证的部分

- 妙思为微信扫码登录，**登录动作只能由你本人完成**；脚本只负责保存与复用会话。
- 会话有效期由腾讯侧决定，但 cookie 自带到期时间，可零成本提前判定（见 5.3.1）。
- 妙思资产库（成品库 / 原料库）抓取**尚未验证**：当前测试账号未关联投放账户、库为空，
  端到端验证用的是灵感广场素材详情页；关联投放账户后建议再补一次验证。
- **网页内扫码登录尚未由人工完成过一次真实扫码**：自动化部分已验证到「二维码就绪、可被网页取回、
  取消后不污染状态」，但「扫码 → 落盘会话」这一步需要真人操作。

## 6 脚本处理逻辑

针对「脚本整理」环节的整体改造：

1. **妙思原网页板块提取** → 填到「视频分析」栏（见 5.2）。
2. **转写文案切分并打标签** → 每段只能有一个标签、不得重复标记。
3. **表头改为标签列** → 以六类标签作表头，用对应标签的**转写原文**填充，**不能改动原文**，
   没有则标记为空。
4. **视频分析栏与结构删减** → 妆造 / 画面场景 / 情绪 / 形式 / 视频链接统一划入「视频分析」栏；
   形式为混剪时妆造 / 画面场景 / 情绪全部留空且只标注一次；脚本表格只保留一行。

### 6.1 导出结构

| 区 | 列 |
|---|---|
| 视频分析（10） | **原视频标题**、性别特征、年龄特征、分镜 / 高光 title、创意标签、妆造、画面场景、情绪、形式、视频链接 |
| 脚本文案（1） | 音频转写原文整段（人工可改，与工作台同源） |
| 标签（6） | 人设、痛点、干货（解决方案）、营销内容（产品介绍）、福利、其他 |

第 1–4 行抬头信息，**第 5 行是分组行**（三组用不同底色区分），第 6 行是列名表头，
**第 7 行是唯一一行数据**。标签列内容由该标签下所有段落按时间顺序用换行拼接，取自转写原文。

#### 6.1.1 两种导出

导出确认页有两个按钮，各自完整走「校验 → 生成 → 下载」，有阻塞项时都停在同一个列表等用户明确
移除后继续：

| 按钮 | 文件 | 结构 |
|---|---|---|
| **导出信息流脚本** | `信息流脚本_YYYYMMDD_HHMMSS.xlsx` | 表头 **序号 / 时间、标签、文案**；按时间轴一段一行，序号在工作表内从 1 起；保留抬头 4 行；一视频一表 |
| **导出信息流素材库** | `信息流素材库_YYYYMMDD_HHMMSS.xlsx` | 6.1 的单行多列结构 |

两者的区别：前者文案列**逐字等于**该段转写原文（不聚合、不改字），给拍摄团队按时间轴对稿；
后者按标签聚合，给素材库归档。两者共用同一份版本快照。

**「创意标签」的展示范围与顺序**（工作台与导出共用同一函数）：

```
定向年龄 → 人群 → 制作形式 → 情绪 → 背景风格 → 场景背景 → 叙事 → 开场钩子 → 结尾钩子 → 行动引导
```

只呈现这 10 项；其余字段（定向性别 / 平台活动 / 事件 / 地域 / 知识产权 / 明星 / 促销 / 核心功能 /
痛点 / 卖点等）**仍照常采集并保存在原网页快照里**，只是不呈现。

### 6.2 六类标签判定口径

| 标签 | 判定口径 |
|---|---|
| 人设 | 说话人的自我身份、职业、经历介绍 |
| 痛点 | 用户遇到的问题、困扰、负面处境，**以及使用场景 / 时间地点情境** |
| 干货（解决方案） | 方法、步骤、知识、解决思路 |
| 营销内容（产品介绍） | 产品 / 服务本身：卖点、功能、成分、参数、效果、资质与背书 |
| 福利 | 优惠、赠品、价格、限时、名额、领取方式与行动引导 |
| 其他 | 确实不属于以上任何一类（纯寒暄、过渡、与主题无关） |

「场景」**已不是标签**：原先单列的「使用场景、时间地点情境」并入「痛点」，因此现行为六类。
程序只做**归一**不做重判：模型给出的标签越界或缺失时归入「其他」并记 `TAG_INVALID` 警告，
保证「每段必有且只有一个标签、不丢段」。

### 6.3 原文保真与段落划分兜底

需求红线是「用转写原文填充，不能对原文作更改」，另一条是「**每段内容不应重复**」，
两条都不能靠提示词约束，必须由程序保证。

- **原文由程序回填**：实测整理模型即使被明确要求「忠实原话」，仍会改写 / 补写多数段落。因此流水线
  在保真校验**之前**执行确定性回填 —— 文案一律改用「该段引用的原始语音片段」的原文拼接，
  模型对文案的改写全部丢弃并留痕。
- **段落划分由程序重建**：模型会给出**相互重叠的引用**（例如第 1 段引用了横跨 60 秒的整块片段，
  后续段落又重复引用它）。`partitionSegments()` 按原始语音片段重建划分，规则五条：① 一个片段只
  归属一段（按段落顺序先引用先归属）；② 模型未引用的片段按时间就近归入覆盖它的段；
  ③ 段落起止由所归属片段的真实时间推导（**不再信模型给的时间**，实测能差 15 秒以上）；
  ④ 没有任何独立片段的段整段丢弃（**绝不留重复文案**）；⑤ 划分后按真实时间重排。

**验收口径**：第 2 段起，每段与前面段落的 6 字片段重合比例应 < 50%；同时「脚本文案 = 各段文案按序
拼接」是一条不重不漏的强校验。过程中可能出现的问题码均为 warn、不阻断出结果：`TEXT_REPAIRED`
（按原文回填）、`DUPLICATE_UTTERANCE`（重复引用按首次归属）、`UNKNOWN_UTTERANCE_REF`、
`UTTERANCE_ASSIGNED`（未引用片段就近归入）、`SEGMENT_DROPPED`（重复段丢弃）、`ORGANIZE_EMPTY`
（模型未返回段落，按语块保留）、`ASR_COARSE_SENTENCE`（有超长片段且无词级时间戳，需人工核对）、
`TAG_INVALID`（标签越界 / 缺失，归入「其他」）。

模型角色因此收敛为：**分段 + 打标签 + 妆造 / 情绪**，不承担文案改写，也不承担「保证不重不漏」。

### 6.4 形式判定与混剪分支

**形式取值**：`混剪` / `AI数字人` / `真人` / `其他`（阈值可配）：

| 顺序 | 条件 | 结论 |
| --- | --- | --- |
| 1 | 画面无连贯主体、由多个独立素材拼接 | 混剪 |
| 2 | AI 画面时长占比 ≥ `AI_VIDEO_RATIO_THRESHOLD`（默认 **0.75**） | AI数字人 |
| 3 | 真人内容占比 ≥ `REAL_PERSON_RATIO_THRESHOLD`（默认 **0.75**） | 真人 |
| 4 | 其余（25%~75% 的中间带） | 其他 |

- 阈值含等号：恰好 75% 归 `AI数字人`，恰好 75% 真人内容归 `真人`。
- 模型无法可靠估计占比时**仍落「其他」**，但**不编造比例**（`ratioEstimated=false`），并在依据字段
  写明原因，便于编导识别需复看的记录。
- 人工纠正入口在「任务信息 → 形式」下拉，只提供上述 4 项；接口对旧取值返回 400。

形式判定为「混剪」时**不再停止解析**：文案照常分段打标签，只是妆造 / 画面场景 / 情绪三项留空
（只标注一次、不做任何推断），并写入一条说明供编导知悉。

## 10 个性化文案改写与数字人口播

### 10.1 要解决的问题与红线

脚本还原链路把参考视频还原成「**别人的**脚本」。这一条要的是「**用自己的 IP 讲同一条内容**」：

```
参考视频已复核脚本 → 提炼结构骨架（段数 / 顺序 / 六类标签）
                    → 注入 IP 资料包（人设 / 资质 / 方法 / 案例 / 产品权益 / 适用条件）
                    → 生成多个版本的自有 IP 口播稿
                    → 编导逐段比较、编辑、选定
                    → 送数字人平台出片
```

**结构由程序裁决，不由模型自由发挥** —— 这是最硬的一条红线：

- **段数一致**：参考 7 段就出 7 段，多一段少一段都判不通过，不自动截断也不自动补。
- **顺序一致**：第 n 段对应参考第 n 段，不许调换（先讲痛点再讲人设 = 废稿）。
- **标签沿用六类且与参考段同标签**：模型写出半角括号的变体也认（先归一化回填规范标签并留一条
  info 级问题项），不再因此废掉整稿。
- **不补引流结尾**：参考稿没有结尾引导，改写稿也不许加；参考段本来就有行动引导的沿用其表达，
  但不新增、不放大、不改写成更强的催单话术。
- **不增删段内内容**：每段字数应贴近对应参考段（**0.7~1.3 倍**）。偏离只**提示不拒绝** ——
  同一段话可长可短属正常创作，但严重偏离往往意味着模型改了该段的作用。

**与「脚本整理」是两条互不影响的链路**：

| | 整理 | 改写 |
| --- | --- | --- |
| 性质 | 忠实转写 | 创作 |
| 内容 | 一个字都不能变 | 全换成自有 IP 的说法 |
| 骨架 | 由模型切分，程序保证不重不漏 | 由参考稿固定，程序强制执行 |
| 兜底 | 程序级原文回填 | 程序级结构裁决（`validateRewrite`） |
| 换模型影响 | 只影响本链路 | 只影响本链路，**不重跑 ASR 与画面理解** |

改写**只烧文本 token**，不重跑语音识别与画面理解，所以单次成本约为一次完整视频解析的 1/4~1/3。

### 10.2 改写模型选型

同一参考视频、同一资料包版本、同一提示词，多家模型各生成多篇对比。

**选型结论**：推荐 **`qwen3.8-flash`** —— 成本最低（约为次选的 1/3）、字数最贴近参考段、多版差异
明显、内容无编造。次选 `qwen3.7-plus`（质量相当、更快，但贵约 3 倍）。`qwen3.8-max` 明显偏贵且
输出偏长，不建议用于本场景。

> `qwen3.8-*` 系列若未显式关闭思考模式会走 reasoning，输出 token 数量级上升 —— 本项目已在适配器里
> 显式关闭。改 `REWRITE_MODEL` 需要**重启 worker**，费用估算会按新模型名自动取档。

### 10.3 IP 资料包（版本化）

资料由 `src/lib/rewrite/docx.ts` **零依赖**解析，按下列板块整理成结构化 JSON 落库：

| 键 | 内容 |
| --- | --- |
| `personal` / `credentials` | 人设与经历 / 资质证书 |
| `method` / `cases` | 理念与方法演示 / 学员与客户案例 |
| `audience` / `offer` / `conditions` | 受众问题 / 课程与产品权益 / 适用条件 |
| `styleSamples` | 风格样例（供模型模仿语气） |
| `boundaries` | **事实边界与禁止表述**（如「不得承诺效果」「团体荣誉不得写成个人荣誉」，渲染时排最前并宣告为硬约束） |
| `gaps` | **待统一字段与缺失资料**（原文自相冲突的价格 / 课时 / 称谓等，要求模型不得自行选一条当事实） |
| `facts` | **可引用事实条目**（带 id，改写稿逐段可追溯引用了哪几条） |

**版本化是硬要求**：

- 导入新文档 = **追加 `v(n+1)` 并把旧版本置为失效**，旧版本不删除、可回看、可重新置为生效。
- **生成任务按版本 ID 锁定输入快照**：已生成的任务永远用当时那一版资料重建输入，**不回读当前生效
  版本** —— 所以换了资料包，旧稿仍可复现、可对比。
- 来源文件名与 `sourceSha256` 一并入库，同文档重导入 / 换文档都能识别。

换版：`npm run rewrite:profile -- "<新文档.docx>" --note "更新说明"`（同文件重导要加 `--force`）；
回看与切换在页面「IP 资料包」。质量体检（`rewrite:profile:check`，只读、零费用）从两个方向看：
**召回**（原文里含禁令措辞的句子的「否定核心」是否被某条事实代表）与**忠实**（每条事实有多大比例
能在原文里找到，用于发现疑似编造条目）。两个反直觉处已写进脚本注释：不能用整句算覆盖率
（模型会把长句压成短祈使句，整句判据会把抽对了的判成漏抽）；召回的分母混着「操作说明」句
（含否定词但不是业务边界，本就不该进事实库）。

### 10.4 数字人口播（鲲之益平台）

**平台**：鲲之益 AIGC。**官方 API 尚未确认**，首版用 Playwright 驱动网页；适配器接口已按
「日后换官方 API」的形状抽好（`AvatarAdapter`），换实现只需新增一个 adapter。

关键设计（都有对应验收项）：

- **独立 worker + 独立单实例锁**：出片是长等待（轮询可达 30 分钟），**不能占用全局串行的视频分析
  队列**。**会话独立于妙思**（不同站点、不同账号，混用会让两边登录态互相覆盖）。
- **形象 / 音色必须唯一匹配**，找不到 / 重名 / 资产被移除时明确报错，**绝不静默换成别的**。
- **只接受已选定修订**；一次只生成**一整条**口播，不调平台二次改写、不自动拆分；超平台单次文本
  上限时提示编导精简，**不自动删减文案**（自动拆分会产出被截断的片子，更难发现）。
- **结果不明一律进「待核对」，绝不自动重提**：已尝试过提交的任务（认 `submittedAt` 而不是
  `vendorJobId`）只走查询 —— 否则「提交成功却没读回 ID」+「会话过期变待登录」凑齐时，下一轮会
  再提交一遍，同一稿件出两条片、重复计费。
- **「按作品名查不到」不等于「确定没提交」**：编导在平台上改名后唯一作品名当场失效，**已经出片
  成功**的任务就可能被判成「确定没提交」，既丢掉交付又放开重复计费。因此必须再确认「列表里没有
  本次提交之后新建的作品」才敢下结论，时间线可疑一律退回「待核对」。
- **以平台作品 ID 为对账钥匙**：ID 不随改名变化。提交瞬间抢读一行，错过也能用「绑定平台作品」
  按 ID 接回（服务端**先核实作品确实存在**再写库，一个笔误就会把任务指到别人的作品上）；
  **刻意不做自动绑定** —— 认错就是把别人的作品当成品交付，且错得无声无息。
- **成品下载后持久化并记录 sha256**（平台链接会过期）；预览 / 下载走**鉴权接口**并支持 `Range`。
  作品列表的列**按表头定位**，不写死下标（平台加列会静默取错值）。

**验收走 Mock**（`AVATAR_ADAPTER="mock"`，默认）。Mock 桩按**作品名**内嵌标记触发各分支
（会话失效、提交结果不明、提交成功但读不回作品 ID、平台报错、长时间生成中、人工接手未完成、
人工接手后会话失效、提交成功但平台侧被改名），让**在真实账号上很难复现的分支**可以稳定回归，
且不花平台额度。

⚠️ **Mock 是默认值，必须在界面上说清**：用户点了「生成数字人视频」，若界面提示「后台会提交到平台」，
而适配器默认是 mock，平台上当然没有记录。现在任务卡片常显适配器模式（「Mock 适配器（不会提交到
平台）」/「真实适配器 · 会话已配置 / 缺登录会话」），创建提示按适配器分叉，并显示**数字人解析进程
是否在运行** —— 进程没起，任务会一直停在「排队中」，这是「平台没有记录」的另一种成因。

⚠️ **「尚未提交」不得伪装成「结果待核对」**：对从未提交过的任务点「重新核对平台记录」，平台必然
查不到。现在改成如实说明「还没提交」、给出该做什么，并把脏状态**修回排队中**。

#### 提交方式：`auto` 全自动 / `assist` 人工接手

`AVATAR_SUBMIT_MODE` 决定「谁来选形象和参数」：`auto`（默认）由适配器选参数并点提交，适合无人值守、
批量出片；`assist` 由**编导**在真实的平台创建页上自己选形象、调参数、点「生成视频」，适合联调期、
平台改版后、需要人工把关参数的场景。

**为什么留一条人工接手的路**：自动提交最脆的几段恰好都在「替平台做参数校验」上 —— 形象 / 音色唯一
匹配、参数滑杆、成片保存文件夹必填、提交按钮可用性判断。这些选择器平台一改版就崩，而崩了之后报出
来的是「视频生成失败，请检查配置参数」这种**没人能诊断的泛化错误**。把这些校验交还给平台自己的 UI，
比猜它的规则可靠 —— 用一点人肉换稳定性。

`assist` 下数字人进程以有头模式打开创建页，**只预填作品名与文案**，然后停在页面上等编导操作。
两种模式**共用同一套状态机与同一套「按唯一作品名确认」逻辑**，差别只在提交那一步由谁操作。
结局分四种：查到作品名 → 平台生成中；**作品名查不到且列表里没有本次提交之后新建的作品** →
判定「确实没提交」（可重新发起，且这是**唯一敢清 `submittedAt`** 的情形 —— 因为「查过列表、确实
没有」是查询之后的结论，不是猜的）；作品名查不到但列表里有新作品 → 改名嫌疑，退回「待核对」；
会话失效、列表都打不开 → 退回「待核对」。**待核对仍算在途**，既不重复提交，也留了接回来的路。

界面配套：卡片标注「人工接手模式（形象与参数由你选）」；状态 chip 显示「人工接手已取消」，
横幅给出确定结论 + 出路（没有提交、不产生费用、可直接重新发起）与取消原因；
**「已取消」不得复用「尚未提交（排队中）」那块提示**（两者判据相同、结论相反，文案必须分叉）；
已取消时「重新核对」禁用。注意窗口开在**运行数字人进程的那台机器**的桌面上（单机部署即本机）。

#### 真实账号联调要点

会话已用真实账号扫码打通，选择器与交互顺序按实测重写。几个影响「会不会误判」的事实：

- 登录凭据是 **`localStorage.token`，不是 cookie** —— 只判 cookie 会假报「会话可用」，
  现在以 token 存在性为硬信号。
- 形象列表是左侧**平铺卡片**（不是按钮、不是弹层），按名字节点精确计数并读回显确认；
  音色入口是 **`div` 不是 `button`**，且弹层定位**必须带 `:visible`**（页面里同时挂着多个弹层，
  隐藏的排在前，否则永远判「没弹出」），关闭要**点弹层内的「确定」**（全局找会点到别的弹层）。
- **成片保存文件夹是提交前必填项** —— 形象 / 音色 / 文本 / 作品名全填好后按钮**仍然不可用**，
  唯一空着的就是它；已按 `AVATAR_SAVE_FOLDER` 选择，**选不到就报错、绝不随便挑一个**
  （会把成片存进别人目录）。该控件选中后搜索框会从 DOM 消失，回读要以容器为锚点。
- 作品名与文件夹搜索框的 placeholder 都含「名称」，已改为显式匹配，避免填错框；
  作品列表状态文案为「创作中 / 创作完成 / 创作失败」，**必须先判「创作中」**再判完成。
- **成品 mp4 在云存储域名下、不在站点主域**，且要**点行内「播放视频」**才拿到真实地址
  （封面列只是快照图）。原白名单只放行站点主域会把成品链接直接拒掉，现按云存储后缀放行。
- 两个安全选择：**不点禁用按钮**（直接点再等会报「已提交但拿不到 ID」，而其实什么都没提交）、
  **截图必须 await**（否则浏览器一关一张没落盘，而截图是判断页面到底变成什么的唯一线索）。

### 10.5 接口与导出

新增接口（全部按**归属鉴权**，他人资源一律 403 / 404）：建改写任务 / 首屏预览
（`POST`、`GET /api/videos/[id]/rewrites`）、任务详情（`GET /api/rewrites/[id]`，参考稿取自任务快照，
并带回最近一条数字人任务 id 供界面刷新后恢复卡片）、重新生成与选定
（`.../regenerate`、`.../select`）、编辑保存（`POST /api/rewrite-variants/[id]/revisions`，
乐观锁、版本冲突返回 409、禁止改段数 / 顺序 / 标签）、资料包版本列表与导入（`GET` / `POST
/api/ip-profiles`）、历史版本置为生效（`.../activate`）、数字人任务建立 / 详情 / 成品预览下载
（`POST /api/avatar-jobs`、`GET .../[id]`、`GET .../[id]/video`）、结果核对（`.../reconcile`，
**不重新提交**）。

**导出新增第三种**：`EXPORT_KIND=REWRITE`「信息流改写稿」，一个任务一张表，列为
`稿件版本 / 序号 / 标签 / 正文 / 预计口播时长（估算）`。「预计口播时长」用「**约 X 秒**」表达 ——
它按字速估算、**不是时间码**，与「信息流脚本」导出的 `序号 / 时间、标签 / 文案` 明确区分，
避免被当成实际时间轴。三种导出的文件名前缀：`信息流脚本_` / `信息流素材库_` / `信息流改写稿_`。

## 11 已知限制与说明

- **音频识别与原定模型不一致**：原定方案要求公网可访问的文件地址，本机部署无法满足，已改走实时
  WebSocket 识别（原因与对比见 4.2），并提供 `ASR_TRANSPORT` 开关可切回。
  **这是需要与需求方确认的一处偏离。**
- 音频识别为**实时推流**，处理耗时与音频时长同阶；长素材的等待时间明显长于异步批处理，
  超时上限已按上限 30 分钟素材放宽到 15 分钟。
- `data/tmp` 下的 PCM 中间文件在每次识别结束后删除；进程被强杀时可能残留，可安全手动清理。
- 妙思「视频分析」板块**只对灵感广场榜单内素材提供**：接口对该范围外的素材返回空骨架，此时相关
  字段按需求标记为空并写明原因，不是抓取故障；也无法通过自行发请求绕过（接口有 CSRF 校验）。
- 六类标签的**分段边界由整理模型决定**，同一素材两次运行的分段数与标签分布可能不同（无随机种子）；
  但「不重不漏」由程序保证，不受模型随机性影响（见 6.3）。文案本身由于程序级原文回填始终与转写
  原文一致，但「一段一个标签」的归类质量仍需编导在复核界面确认。
- Mock 模式下的指纹不进入判分：验收用的素材是合成的画面与正弦音轨，只验证流程与格式，
  不用于评估识别质量。
- `data/` 目录（数据库、媒体缓存、取样帧、导出）默认保留至用户删除，删除视频会同步清理其版本、
  取样帧、媒体与相关合并导出文件。
- 升级 Next.js / Prisma 前请先执行 `npm run db:push` 并保留 `data/app.db` 的可恢复副本。

改写与数字人专项：

- **改写是创作，不是转写**：脚本还原链路的原文保真保证（一个字不改）**只适用于该链路**，
  改写稿内容与参考段完全不同是**预期行为**，不要拿原文保真校验去卡改写稿；改写稿的约束是
  「结构一致」，由 `src/lib/rewrite/validate.ts` 单独裁决。
- **改写仍受模型随机性影响**：多版本之间、两次运行之间，表达与分段长度会有差异。结构不变由程序
  保证，但**哪一版更好仍需编导判断** —— 多版并列展示就是为了这个。
- **数字人平台是第三方网页，不是稳定 API**：官方 API 未确认，当前适配器依赖页面结构，平台改版会
  导致选择器失效（失败时每步留截图便于定位）；最脆的参数选择器已有 `assist` 模式兜底。
- **平台单次文本上限尚未核实**（先给保守值）。超限时只提示、不自动拆分、不删减文案。
- **IP 资料包内容是业务资料，不进版本控制**：`data/` 已整体忽略，仓库内不含资料原文。资料包的
  版本化只解决「换文档」的可追溯性，**不解决内容准确性** —— 引用是否有夸大，仍需编导上线前核对。
- **改写生成在 HTTP 请求内同步完成**（多篇约 35~90 秒），期间页面要一直开着。本地部署无网关超时，
  所以够用；但**请求被中途打断（关标签页 / 杀进程）时该任务会停在运行中**，没有像视频解析那样的
  断点恢复机制（页面会如实标成「已中断 / 可能已中断」并给出重新生成入口）。若日后要上服务器或
  加大版本数，应改为「入队 + worker 推进」。
- **改写稿的「预计口播时长」是估算值**（按字速折算），不是真实时间码；实际出片时长以平台为准。
  改写稿导出**不含参考视频的原始时间码** —— 改写后文案长度已变，套用原片时间码会误导拍摄团队。
- 数字人成品落 `data/avatars/`，与视频媒体同样默认保留至用户删除。
